# 06. 전투 HUD·전조·핑·접근성

상태: 구현·화면 검토 대기 · 근거: 프로토타입 기획서 §6–7; GDD §7

## HUD 정보 [기획]

| 영역 | 표시 정보 | 갱신 기준 |
|---|---|---|
| 플레이어 | 본인·동료 HP/스태미나, 잡힘·전투 불능·넘어짐 | 서버 확정 상태와 예측 가능한 본인 입력 |
| 사슬 | 경로 길이, 여유/긴장/과긴장, 유연/고정, 감김/낚아챔, 제압 게이지 | 서버 판정값; 장식 사슬 위치 사용 금지 |
| 보스 | HP, 코·앞다리 내구도, 페이즈 | 서버 확정값 |
| 행동 안내 | 현재 가장 우선인 대응, 구조 위치, 공동 당기기 실패 이유 | 해당 사건의 유효 시간 동안만 |
| 방향 | 화면 밖 동료의 방향과 거리 | 카메라 기준 매 프레임 보간 |

상태는 **색과 함께 아이콘·텍스트·소리**로 전달한다. 색만으로 구분하지 않는다. [기획] 같은 사건의 결과 피드백은 양쪽 클라이언트에서 동일하다. [명세 제안]

## 보스 전조 [기획 + 명세 제안]

기술 ID, 대상, 전조 시작·판정 예정 시각을 받아 바닥 표시/사슬 강조/보스 애니메이션을 동기화한다. 낚아채기는 사슬 경로와 HUD를 함께 강조하고, 회전은 잡힌 사람·자유 플레이어의 행동 안내를 분리한다. 전조 종료 전 피해를 적용하지 않는다. 시각 효과의 폭·길이는 서버 히트박스와 같아야 한다.

## 핑 4종 [기획]

`접근`, `당겨`, `해제`, `구조`를 즉시 보낼 수 있다. 발신 플레이어, 종류, 서버 틱을 표시하며 같은 종류의 연속 입력은 화면과 음성 피드백이 쌓이지 않도록 제한한다. 제한 시간은 데이터 값이다. [명세 제안]

## 테스트용 옵션 [기획]

자막 크기 변경과 화면 흔들림 끄기를 제공한다. 게임패드 진동·소리의 정식 세부 옵션은 이번 프로토타입의 필수 범위가 아니지만, 색 외 대체 신호는 필수다. [기획 해석]

## 완료 기준

1. 두 사람이 사슬 상태와 피격 원인을 화면에서 구분할 수 있다.
2. 보스 전조 표시와 실제 판정의 시작·끝·범위가 일치한다.
3. 화면 밖 동료 방향 표시가 회전·구조 중에도 유지된다.
4. 자막 크기와 화면 흔들림 옵션이 재시작 없이 적용된다.
5. 4종 핑을 각자 보낼 수 있고 상대에게 같은 종류·시각으로 보인다.

## 현재 구현과 검증

오른쪽 HUD에 두 플레이어 HP·스태미나·상태, 사슬 경로 길이와 제압 게이지, 보스 HP·부위 내구도·페이즈, 전조 남은 시간과 대응 문구를 표시한다. 화면 밖 동료에게 방향·거리를 표시한다. 보스 기술별 바닥 선은 서버 판정에 사용한 범위 값을 읽는다. 색·텍스트·짧은 소리로 전조와 핑을 알린다. `1`~`4` 핑은 발신자와 서버 틱을 전달하며 같은 종류는 1.5초간 반복 제한한다. `A-/A+` 안내 글자 크기와 화면 흔들림 옵션은 즉시 적용한다.

두 인스턴스 로그에서 양쪽 플레이어가 네 종류 핑을 모두 같은 종류·발신자·서버 틱으로 받은 것을 확인했다. 실제 화면의 가독성·화면 밖 화살표·옵션 조작과 전조 도형의 시각 정합성은 수동 플레이 검토가 남아 있다.
