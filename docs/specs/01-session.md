# 01. 접속·진행·승패·결과

상태: 사용자 검토 반영 · 1·2번 구현 검증 중 · 근거: 프로토타입 기획서 §3–4, §8

## 목적과 범위

정확히 두 사람이 같은 사냥에 입장해 준비, 튜토리얼, 보스전, 결과까지 한 세션을 완주한다. [기획] 초대 코드 또는 개발자 로비 중 하나를 제공한다. 매치메이킹·재접속·호스트 이전은 범위 밖이다.

## 상태와 전이 [명세 제안]

| 상태 | 진입 조건 | 허용 작업 | 종료 조건 |
|---|---|---|---|
| Lobby | 방 생성/참가 성공 | 2명 슬롯 확인, 준비 토글 | 두 슬롯 준비 완료 |
| Tutorial | 두 슬롯 준비 완료 | 튜토리얼 목표 수행 | 양쪽 목표 완료 |
| Combat | 튜토리얼 완료 | 보스전, 구조, 일시 정지 없는 타이머 | 승리/실패 중 하나 확정 |
| Result | 서버가 결과 확정 | 결과 조회, 로비 복귀 | 양쪽 퇴장/로비 복귀 |
| Disconnected | Combat 이전/중 필수 연결 종료 | 이유 표시 | 개발자 로비 복귀 |

- [기획] 최대·최소 인원은 2명. 한 명만 준비한 상태에서는 시작하지 않는다. 튜토리얼을 생략하는 개발 플래그는 플레이테스트 빌드에서 숨긴다. [명세 제안]
- [기획] 보스 HP가 0이면 승리. 두 플레이어가 동시에 전투 불능이거나 전투 시작 후 **18분**이 지나면 실패. 결과가 같은 서버 틱에 겹치면 **보스 HP 0을 우선**한다. [명세 제안]
- [기획] 보스전 목표 시간은 10~15분이며 18분이 강제 종료 상한이다. 타이머는 보스전 진입 시 시작하고 결과 확정 시 멈춘다. [명세 제안]
- 전투 중 연결이 끊기면 명시적 실패 화면을 보여 준다. 네트워크 오류 종료는 보스에게 패배한 횟수와 별도로 집계한다. [기획 + 명세 제안]

## 데이터와 출력

`SessionState`, `playerSlots[2]`, `readyFlags[2]`, `combatStartTick`, `resultReason`, `bossHp`, `revivesUsed`, `staggerCount`, `chainMechanicAttempts/Success`, `damageCauseCounts`를 서버가 보유한다. 결과 화면은 승패, 시간, 제압 횟수, 사슬 기술 대응률, 피격 원인을 표시한다. [기획]

## 경계 조건

- 준비 취소나 퇴장 시 다른 플레이어의 준비 상태는 유지하되 시작 조건을 다시 평가한다. [명세 제안]
- 전투 종료가 확정된 뒤 늦게 도착한 피해·구조 입력은 결과를 바꾸지 않는다. [명세 제안]
- 결과 전환은 서버의 단일 `SessionEnded` 이벤트로 발생한다. 양쪽 화면의 승패·시간·원인 값이 같아야 한다. [명세 제안]

## 완료 기준

1. 서로 다른 두 클라이언트가 생성/참가 → 준비 → 튜토리얼 → 전투 → 결과 → 로비 복귀를 한 번 완주한다.
2. 1명만 준비하거나 3번째 클라이언트가 참가하려 할 때 시작하지 않는다.
3. 보스 HP 0, 동시 전투 불능, 18분 경과, 연결 끊김의 종료 이유가 각각 분리되어 양쪽에 일치하게 표시된다.
4. 동일 서버 틱의 승패 충돌이 위 우선순위대로 한 번만 확정된다.
