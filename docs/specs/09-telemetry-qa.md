# 09. 계측·테스트·수용

상태: 검토 초안 · 근거: 프로토타입 기획서 §2, §8–12

## 현재 자동 회귀 범위

`tools/run_regression.ps1`은 개발용 전용 서버 1개와 클라이언트 2개를 사례마다 새로 실행한다. 현재 튜토리얼 5단계와 전투 전환, 보스 기술 대응, 플레이어별 첫 번째·두 번째 다운 구조(3초·6초), 보스 처치 결과를 확인한다. 각 사례의 서버·양 클라이언트 로그와 `summary.json`은 `Builds/Regression/` 아래에 저장된다. 실행 전 Unity 메뉴 `Chainbound Raid > Build Client and Dedicated Server`로 개발용 빌드를 만든다.

2026-10-30 자동 시험에서는 네 사례가 모두 통과했다. 이 시험은 실제 사람의 조작, 지연·손실 조건, 30분 장기 연결, 전조의 가독성, 튜토리얼 3~5분 목표를 대신하지 않는다. 아래의 계측 계약과 외부 사용성 시험은 후속 작업이다.

## 기록 계약 [기획 + 명세 제안]

모든 핵심 이벤트는 `sessionId`, `eventId`, `eventSequence`, `serverTick`, `eventType`, `actorId`, `targetId`, `bossMoveId`, `chainState`, `pathLength`, `playerPositions`, `outcome`, `reasonCode`를 기록한다. 해당 이벤트에 필요한 경우 `telegraphStartTick`, `hitTick`, 양쪽 입력 틱, 피해량, 제압 게이지, RTT·손실·보정 거리도 추가한다. 세션 식별자는 임의 ID를 사용하고 개인 정보는 저장하지 않는다. 영상은 참여자 동의가 있는 시험에서만 촬영한다. [기획]

## 자동·수동 시험

| 종류 | 핵심 사례 | 통과 판단 |
|---|---|---|
| 규칙 시뮬레이션 | 6.99/7/8/9m 경계, 상태 우선순위, 감김 1개 제한, 이중 잡힘 금지, 기술별 피해 1회 | 반복 결과 일치 |
| 기능 플레이 | 기술 5개 각각 20회 이상, 낚아채기 사전/사후 대응, 회전 안전 경로·구조 | 전조·피해·복귀 경로 재현 |
| 네트워크 | 0/80/150ms RTT × 0/2% 손실, 각 30분 | 사건 순서 일치, 진행 불가 0건 |
| 외부 사용성 | 8쌍 이상, 설명 없는 첫 시도 → 튜토리얼 → 2회 사냥 | 아래 경험 지표 측정 |
| 회귀 | 낚아채기/회전/구조/다운 변경 후 재실행 | 기존 사건·상태 불변식 유지 |

## 기능 수용 게이트 [기획 요약]

1. 두 명이 한 세션의 로비→전투→결과를 완주한다.
2. 사슬 경계·상태·감김점 판정이 일관되고 시각 물리에 영향받지 않는다.
3. 낚아채기에는 사전과 사후 대응이 모두 있다.
4. 회전에는 이중 잡힘이 없고 `<7m` 안전 경로에서 자유 플레이어 피해가 없다.
5. 공동 제압은 자세·접지·각도·입력 겹침 모두 충족할 때만 가능하다.
6. 서버와 양 클라이언트의 핵심 사건 순서가 같고 1m 이상 시각 순간이동 0건을 목표로 한다.
7. 연속 조작 불능은 6초 이하이며 치명적 진행 불가·재현 가능한 무적/무한 제압 버그가 없다.

## 경험 지표 [기획의 가정]

튜토리얼 후 외부 8쌍 이상이 두 번씩 플레이한다. 참여자 70% 이상이 사슬 때문에 의도적으로 위치를 바꿨다고 답하고, 80% 이상이 피격 원인을 설명하며, 공동 당기기 시도 중 60% 이상이 성공하면 다음 제작 단계로 진행한다. 이 표본은 개발 판단 자료이며 출시 품질의 통계적 보증이 아니다.

## 판단과 보고 [기획]

- **진행:** 기능 게이트와 경험 지표 3개를 모두 충족.
- **수정:** 핵심 재미는 있으나 지표가 미달이면 전조·UI·거리 문턱을 먼저 조정하고 4쌍 이상으로 재시험.
- **방향 변경:** 두 차례 수정 후에도 의도적 위치 선정이 50% 미만이거나 피격 이유 설명이 60% 미만이면 핵심 사슬 기믹 재설계.

결과 보고에는 빌드 버전, 시험 조건, 표본 수, 각 지표의 분자/분모, 실패 사례 재현 절차, 남은 결함을 포함한다. [명세 제안]
