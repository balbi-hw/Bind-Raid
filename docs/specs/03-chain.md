# 03. 하이브리드 사슬 판정·상태·표현

상태: 검토 초안 · 근거: 프로토타입 기획서 §5, §8; GDD §5

## 다음 작업 범위

이번 구현은 **3번 사슬 기능만** 대상으로 한다. 현재 2인 네트워크 전투 씬에 서버 권위 경로 길이, 7/8/9m 거리 상태와 이동 제약, 표시용 사슬, 지정 앞다리 감김점 하나, 낚아챔 시 코 잡기점으로 경로 전환·복귀할 수 있는 상태 경계를 연결한다. 낚아채기 기술의 전조·피해·공동 당기기 성공 판정은 각각 5번 보스와 4번 협동 기능의 범위이므로 이번에는 구현하지 않는다. 기존 초기 실험 씬의 `HybridChain`은 참고용이며, 네트워크 전투 씬의 완성된 사슬 기능으로 간주하지 않는다.

## 판정 경로 [기획]

사슬 양 끝은 플레이어 허리 앵커다. 서버는 두 끝점과 **최대 한 개**의 지정된 앞다리 감김점 또는 보스 코 잡기점으로 경로를 계산한다. 감김점이 없으면 양 끝 거리, 있으면 두 구간 거리의 합이 `pathLength`다. 일반 지형과 기둥에는 감기지 않는다. 렌더링 세그먼트·흔들림은 판정 경로·피해·충돌에 영향을 주지 않는다.

## 거리 규칙 [기획 수치 + 명세 제안]

| 경로 길이 | 기본 거리 상태 | 이동 영향 |
|---|---|---|
| `< 7m` | 여유 | 제약 없음 |
| `7m ≤ d ≤ 8m` | 긴장 | 방향·거리 경고 |
| `8m < d ≤ 9m` | 긴장 + 완충 | 사슬을 늘리는 입력을 감속·제한 |
| `d > 9m`를 시도 | 과긴장 | 최대 속도의 끌림·스태미나 피해, 연속 노출 시 짧은 넘어짐 |

경계의 `7m`는 긴장, `8m`는 아직 완충 시작 전, `9m`는 과긴장 전으로 정한다. [명세 제안] 서버는 이동 명령을 처리한 뒤 유효 경로를 재계산하며, 이미 잡힘·전투 불능인 플레이어에게 과긴장 넘어짐을 다시 부여하지 않는다.

## 상태 우선순위 [기획 + 명세 제안]

표시 상태는 `잡힘/전투 불능/넘어짐 > 낚아챔 > 감김 > 과긴장 > 긴장 > 여유`다. 상위 상태가 끝나면 남은 앵커와 거리로 재평가한다. 상위 상태가 낮은 상태 데이터를 지우지 않는다. `잡힘`과 `전투 불능`은 플레이어별 상태이며, 두 플레이어가 동시에 잡힌 상태는 금지한다. UI는 각 플레이어의 행동 지시와 공유 사슬 상태를 따로 표시한다.

## 앵커와 중첩

- 지정 앞다리 진입 조건 충족 시 감김점 하나를 부여한다. 기존 감김점이 있으면 추가 생성하지 않는다. [기획]
- 낚아챔은 현재 감김을 잠시 비활성화한다. 낚아챔 종료 시 감김 앵커가 유효하고 보스 지정 부위에 남아 있으면 복귀, 아니면 여유/긴장으로 재계산한다. [기획]
- 코 잡기점과 앞다리 감김점을 동시에 판정 경로에 넣지 않는다. 해제·부위 파괴·보스 이탈 시 앵커를 제거한다. [명세 제안]
- 서버 권위 위치가 시각 사슬과 일시 어긋나면 시각 사슬만 보간한다. 플레이어를 시각 사슬에 맞춰 순간이동시키지 않는다. [기획]

## 데이터 계약

서버 상태: `playerAnchorIds[2]`, `activeAnchorId?`, `suspendedWrapAnchorId?`, `pathLength`, `distanceBand`, `displayState`, `stateEnterTick`. 설정값: `warningLength=7`, `nominalLength=8`, `hardLength=9`, 완충 감속률, 끌림 속도 상한. 수치 7/8/9m는 플레이테스트 가정이다.

## 완료 기준

1. 6.99/7/8/9m 경계와 9m 초과 시도가 100회 반복에서도 같은 상태를 낸다.
2. 감김점은 지정 앵커 하나만 존재하고 일반 지형과 시각 사슬 충돌로 상태가 바뀌지 않는다.
3. 낚아챔·감김·넘어짐 종료 후 올바른 상태로 복귀한다.
4. 다운 중 과긴장 다운 중복, 이중 잡힘, 2개 감김점이 발생하지 않는다.
