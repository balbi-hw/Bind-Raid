## 공통 원칙

- 근거: [프로토타입 기획서](../CHAINBOUND_RAID_Prototype_Plan.md)를 우선한다. 일반 출시 범위와 충돌하면 프로토타입의 **2페이즈·무기 1종·18분 제한**을 적용한다. [전체 GDD](../CHAINBOUND_RAID_GDD.md)는 배경과 장기 방향이다.
- **[기획]**은 기존 기획서에 있는 요구다. **[명세 제안]**은 구현·검증을 위해 이 초안에서 정한 세부 규칙이다. **[검토 필요]**는 사용자 결정 전까지 확정하지 않는다. 수치가 기획서에서 [가정]으로 표기되었다면 여기에서도 초기 튜닝값이다.
- 이 문서는 구현 승인이 아니라 검토용이다. 현재 빌드가 본 명세를 충족한다는 뜻이 아니다.
- 모든 거리 단위는 Unity 월드 미터, 시간은 초, 피해 비율은 해당 플레이어 최대 HP 기준이다. 게임플레이 판정은 서버 시각을 기준으로 한다.
- 한 사건은 서버에서 한 번 확정하고 `sessionId / sequence / serverTick / eventId / actorId / targetId / payload`로 기록한다. 표시용 사슬 물리는 게임플레이 판정에 참여하지 않는다.

## 이번 검토에서 결정할 항목

1. **다운의 구분:** 체력 0의 `전투 불능`과 발 구르기 등의 짧은 `넘어짐`을 별개 상태로 다룬다. 전투 불능 구조 시간은 플레이어별 누적 횟수에 따라 3초, 6초, 9초…이며 구조 횟수 제한은 없다. [사용자 검토 반영]
2. **회전 중 협동 제압:** 잡힌 플레이어는 일반 당기기를 할 수 없으므로, 회전 기술의 대응은 자유 플레이어의 접근·구조와 잡힌 플레이어의 속도 저하 입력으로 한정한다. 기존 앞다리 감김은 회전 종료 후 복귀할 수 있다. [검토 필요]
3. **사슬 낚아채기 피해:** 실패 시 각 플레이어에게 피해를 독립적으로 한 번씩 적용한다. HP를 공유 자원으로 만들지 않으며, 최대 HP 비율의 고정 상한 없이 공격력·방어력 계산과 플레이테스트로 조정한다. [사용자 검토 반영]
4. **서버 배치:** 전용 서버와 호스트 권위 방식 중 어느 쪽을 프로토타입 기준으로 삼을지 미정이다. 양쪽 모두 동일한 권위 규칙을 요구한다. [검토 필요]
5. **보스 공격 상세 수치:** 공격 반경·돌진 거리·피해량·제압 게이지의 절대값은 플레이테스트 전까지 데이터 자산의 초기값으로 두고, 명세에서는 검증 가능한 관계와 상한을 우선한다. [검토 필요]

## 구현 순서 제안

`02 플레이어` → `03 사슬` → `04 협동` → `05 보스` → `06 UI` → `07 네트워크` → `01 세션` → `08 튜토리얼` → `09 계측·수용` 순으로 기능을 만들되, 네트워크로 옮길 게임 상태는 처음부터 서버 권위 인터페이스로 분리한다. 이 순서는 기획서의 12주 일정과 별도로, 의존성 기준의 작업 순서다.
