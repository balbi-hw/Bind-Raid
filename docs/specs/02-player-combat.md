# 02. 3인칭 플레이어·기본 전투

상태: 사용자 검토 반영 · 1·2번 구현 검증 중 · 근거: 프로토타입 기획서 §3, §7; GDD §4

## 입력과 행동

| 행동 | 입력 의미 | 조건 | 결과 |
|---|---|---|---|
| 이동/카메라 | 2축 이동, 2축 시점 | 전투 불능·잡힘이 아님 | 카메라 기준 지상 이동, 벽 충돌 |
| 질주 | 유지 | 스태미나 잔량 있음 | 빠른 이동, 지속 소모 [명세 제안] |
| 구르기 | 누름 | 접지, 스태미나 20 이상, 행동 가능 | 20 소모, 짧은 이동·회피 판정 [기획 수치] |
| 약공격 | 누름 | 행동 가능 | 무기 1종의 기본 연계, 보스 HP·부위 내구도 피해 |
| 강공격 | 누름 | 행동 가능, 스태미나 15 이상 | 15 소모, 큰 빈틈과 부위 피해 [기획 수치] |
| 록온 | 누름 | 유효 보스 부위가 보임 | 몸통/코/앞다리 대상 선택 |

이번 단계에서는 키보드·마우스만 지원한다. 게임패드와 플레이어용 재매핑 화면은 제외한다. 입력 바인딩은 이후 교체할 수 있도록 데이터로 분리한다. 현재 로컬 두 키보드 입력은 개발 임시 조작이며 최종 2클라이언트 입력 계약으로 쓰지 않는다. [사용자 검토 반영]

## 플레이어 상태 [명세 제안]

`Free → Attack/StrongAttack/Dodge/HitReaction/Knockdown/Grabbed/Incapacitated`로 구분한다. `Knockdown`은 짧은 넘어짐이며 HP가 남아 있으면 자동 회복한다. `Incapacitated`는 HP 0이고 동료의 구조가 필요하다. 첫 전투 불능은 3초, 같은 플레이어의 두 번째는 6초, 세 번째는 9초로 구조 유지 시간이 늘어난다. 누적 전투 불능 횟수는 플레이어별로 보관하며 구조 후에도 초기화하지 않는다. 잡힘·전투 불능에서는 이동/공격/구르기/사슬 자세 변경이 불가하다. 피해는 서버가 확정하며 동일 공격 인스턴스는 같은 플레이어에게 한 번만 적용한다. [사용자 검토 반영]

## 카메라 [기획 + 명세 제안]

각 클라이언트는 자기 캐릭터를 따르는 3인칭 카메라를 가진다. 목표 기본 거리 4.5m는 가정이며 벽 가림을 보정한다. 록온 시 대상 부위를 시야에 유지하되 플레이어의 이동 입력은 보존한다. 동료가 화면 밖이면 방향·거리 표시는 HUD가 담당한다. 회전 기술 중 강제 카메라 회전·화면 흔들림은 끌 수 있어야 한다.

## 피해·스태미나 [명세 제안]

- 스태미나는 0~100. 지속 소모/회복 속도는 데이터 자산으로 조정한다. 0 미만으로 내려가지 않는다.
- 피해량에 최대 HP의 고정 비율 상한을 두지 않는다. 공격 데이터와 공격력·방어력 값을 받아 계산하는 경계를 두어 이후 성장·장비 로직을 추가할 수 있게 한다. 회피 판정과 실제 피격 시각은 서버 틱으로 결정한다. [사용자 검토 반영]
- 보스에게 주는 공격은 `attackInstanceId`, 대상 부위, 피해, 부위 내구도 피해를 한 번씩 기록한다. 사슬 자체는 일반 지속 피해를 주지 않는다.
- 프로토타입 공통 무기 1종만 포함한다. 두 번째 무기와 제작 경제는 제외한다.

## 완료 기준

1. 두 클라이언트 각각이 독립적으로 이동·카메라·구르기·약/강공격·록온을 사용할 수 있다.
2. 스태미나 부족, 잡힘, 넘어짐, 전투 불능에서는 해당 행동이 정확히 거부되고 이유가 로그에 남는다.
3. 보스 몸통·코·앞다리 피격이 구분되어 HP와 부위 내구도가 중복 없이 갱신된다.
4. 카메라 가림과 동료 화면 밖 상황에서도 본인·보스·동료의 위치를 파악할 수 있다.

## 2026-10-31 공격 개선 구현

공격은 무기 설정의 준비·타격·회복 구간을 사용한다. 전방 캡슐 범위와 실제 부위 판정체가 겹칠 때만 타격 구간에 피해를 적용하며, 같은 공격 인스턴스는 한 대상에게 한 번만 적중한다. 록온 부위가 실제 범위 밖에 있으면 해당 부위에 피해를 주지 않는다. 벽을 사이에 둔 명중도 차단한다.

허용된 후딜레이에서 다음 공격을 한 개 예약할 수 있고 수명이 지나면 해제한다. 피격·잡힘·넘어짐·전투 종료 시 취소하며, 설정된 회복 구간에서는 회피로 끊을 수 있다. 공격 중 이동과 방향 전환도 무기 데이터로 제한한다. 동작과 명중 표현은 서버 공격 시각·확정 사건을 따른다.

무기 데이터는 `Assets/Settings/CommonWeaponSettings.asset`, 현재 보스의 부위 배치는 `Assets/Settings/MammothHitboxLayout.asset`에서 조정한다. 별도 최소 씬에서 두 클라이언트 접속 검사를 통과했으며, 원본 씬의 모델·동작 정합성과 조작감은 플레이 검토가 필요하다. 상세 확인 범위는 [개선 실행 계획](../CHAINBOUND_RAID_Gameplay_Improvement_Plan.md)의 2단계 구현 기록을 따른다.
