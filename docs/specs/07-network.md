# 07. 2인 네트워크·서버 권위

상태: 검토 초안 · 근거: 프로토타입 기획서 §3, §7–9; GDD §8

## 소유권 [기획]

서버가 플레이어의 유효 위치, 사슬 경로·상태, 보스 AI, 피해, 구조, 공동 당기기, 승패를 확정한다. 클라이언트는 자기 이동의 즉각적인 반응을 예측하고 서버 결과로 보정한다. 동료·보스·장식 사슬은 보간한다. 클라이언트의 ‘성공’ 표시가 서버 확정보다 먼저 확정형으로 나타나서는 안 된다. [명세 제안]

## 메시지 계약 [명세 제안]

| 메시지 | 방향 | 필수 내용 |
|---|---|---|
| PlayerInput | 클라이언트 → 서버 | playerId, inputSequence, clientTick, 이동/카메라/공격/회피/자세/당기기/구조/핑 |
| WorldSnapshot | 서버 → 클라이언트 | serverTick, 플레이어·보스 위치/상태, 사슬 경로/상태, HP/스태미나/게이지 |
| GameplayEvent | 서버 → 클라이언트 | sessionId, eventSequence, serverTick, eventId, actor/target, 기술·피해·구조·제압 결과 |
| SessionEvent | 서버 → 클라이언트 | 준비, 전투 시작, 페이즈 전환, 승패, 연결 종료 이유 |

서버는 중복 `inputSequence`를 재실행하지 않는다. 클라이언트는 중복 `eventId`를 표시·피해 적용에 다시 사용하지 않는다. 이벤트 역순 도착 시 sequence 순서로 적용하거나 스냅샷으로 복구한다. [명세 제안]

## 공동 입력과 지연 [기획]

서버 시각에서 두 사람의 당기기 유지가 0.8초 겹쳐야 한다. 클라이언트 입력 타임스탬프 보정은 최대 100ms이며, 실제 위치·자세·접지·각도·면역 조건을 서버가 재검증한다. 목표 RTT는 80ms, 시험 조건은 150ms와 2% 손실까지다. 전용 서버/호스트 권위 중 배치는 미정이다. [검토 필요]

## 보정·끊김 [기획 + 명세 제안]

본인 이동 예측이 서버와 어긋나면 게임 상태는 서버로 수렴한다. 화면의 사슬은 짧게 보간하며 장식 위치를 판정에 역전파하지 않는다. 전투 중 접속이 끊기면 재접속 대신 명시적 네트워크 실패 화면으로 종료한다. 한 명의 연결이 끊긴 채 보스 AI가 진행되는 세션은 유지하지 않는다. [명세 제안]

## 완료 기준

1. 0/80/150ms RTT와 0/2% 손실 조건에서 각 30분씩 두 클라이언트가 한 판을 완주한다.
2. 서버·양 클라이언트의 승패, 피해, 잡힘, 제압 이벤트 순서 불일치가 0건이다.
3. 150ms 조건에서도 낚아채기·회전의 대응 입력이 서버에서 일관되게 판정된다.
4. 30분 시험에서 본인 캐릭터가 시각 보정으로 1m 이상 순간이동해 보이는 사례 0건을 목표로 한다.
5. 끊김은 무한 대기·재접속 시도 대신 명확한 실패 이유와 로비 복귀를 제공한다.
