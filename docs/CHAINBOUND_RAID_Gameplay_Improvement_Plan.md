# CHAINBOUND RAID — 조작감·전투 개선 실행 계획

작성일: 2026-10-31 · 상태: 1~6단계 코드 구현·자동 검사 완료 / 전용 동작 자산·실제 플레이 품질 검토 대기

## 목적과 적용 범위

1차 플레이테스트에서 확인된 전반적인 어색함을 줄이기 위해 이동 반응 → 공격 판정·동작 동기화 → 애니메이션 전환 → 카메라 → 사슬 → 보스 판단 순서로 개선한다. 이 문서는 실행 계획과 구현 기록을 함께 관리한다. 코드 구현, 동작 자산 확보, 사람이 확인하는 품질 수용을 구분한다.

사용자 요구: 게임의 지속적인 개발을 고려하여 현재 프로토타입의 모델, 씬, 무기, 보스, 화면 구성에 종속된 코드를 추가하지 않는다. 기존 코드는 단계별로 교체하며 전체를 한 번에 재작성하지 않는다. 정식 계측·분석 시스템과 대규모 수용 시험 구현은 사용자 결정에 따라 후순위로 둔다. 각 변경의 기본 동작 확인은 진행한다.

기존 `docs/specs/01~09`의 게임 규칙을 유지한다. 이 계획은 해당 기능의 실행 구조와 표현을 개선하며, 피해량·사슬 거리·제압 조건 등을 임의로 변경하는 승인이 아니다. 초기 튜닝값과 새 조작 규칙은 변경 근거를 남긴다.

## 공통 설계 원칙

- 입력 의도, 서버 판정, 화면 표현을 분리한다. 애니메이션·카메라·장식 사슬이 피해나 서버 위치를 결정하지 않는다.
- 이동·공격·자세·구조의 행동 가능 여부를 공통 상태 규칙으로 관리한다. UI와 개별 기능이 같은 조건을 따로 구현하지 않는다.
- 시간 기반 게임 판정은 공통 서버 시뮬레이션 시각을 사용한다. 렌더링 프레임이나 요청 도착 간격을 판정 시간으로 쓰지 않는다.
- 속도·공격 구간·부위·카메라·사슬·AI 설정은 용도별 데이터 자산으로 분리한다. 코끼리 모델의 이름, 특정 좌표, 애니메이션 문자열을 공통 판정에 넣지 않는다.
- 씬에서 의존성을 연결하고 생성·해제 시 참조를 등록한다. 핵심 처리에서 전역 인스턴스 탐색이나 매 프레임 객체 검색에 의존하지 않는다.
- 네트워크 전송 코드는 입력과 상태를 전달한다. 게임 규칙을 RPC 본문에 직접 쌓지 않는다. 동일한 규칙을 서버 실행과 본인 이동 예측에 재사용한다.
- 필요한 책임부터 분리한다. 미래의 모든 기능을 위한 범용 프레임워크나 불필요한 인터페이스 계층은 만들지 않는다.
- 2인 협동은 현재 게임 규칙이다. 이를 무조건 다인용으로 일반화하지 않는다. 다만 역할과 대상 참조를 클라이언트 접속 순번이나 특정 모델에 고정하지 않는다.
- 한국어·영어는 안정적인 문구 ID와 번역 자료로 관리한다. 완성된 영문 문자열 일부를 치환하는 현재 방식은 UI 변경 시 교체한다. 숫자·대상 이름은 서식 인수로 전달한다.

## 단계 1. 이동 반응과 상태 처리

### 문제와 목표

현재 `RaidPlayer.SubmitMoveRpc`에서 요청 도착 시간 차이를 이동량으로 사용한다. 지연과 요청 집중에 따라 이동 반응이 달라질 수 있다. 내 캐릭터는 입력 즉시 반응하고 서버 판정으로 수렴해야 한다.

### 작업

1. 입력 수집, 이동 계산, 네트워크 송수신을 분리한다. 이동 계산은 입력 명령·현재 상태·고정 시간 간격·이동 설정을 받도록 한다.
2. 이동 입력에 순번을 부여한다. 서버는 일정한 시뮬레이션 간격으로 최신 유효 입력을 소비하고 마지막 처리 순번을 돌려준다. 일회성 회피 입력은 중복 처리하거나 유실하지 않는다.
3. 본인 화면은 같은 이동 규칙으로 예측한다. 서버 응답에서 확인된 입력을 제거하고 미확인 입력을 재적용한다. 원격 캐릭터는 보간한다.
4. 충돌과 사슬처럼 완전히 동일하게 재현하기 어려운 조건은 서버를 최종 기준으로 삼는다. 보정은 판정 위치와 표시 위치를 구분해 처리한다.
5. 이동·공격·피격·구조 상태의 종료를 서버 시뮬레이션에서 처리한다. 다음 이동 요청이 와야 상태가 풀리는 의존성을 제거한다.
6. 입력 중단·포커스 상실·연결 종료 시 이동과 유지 입력을 해제한다. Esc 설정 조작 중 허용할 이동을 명시하고 마우스 UI 클릭은 공격으로 전달하지 않는다.

### 완료 기준

- 입력 직후 본인 이동이 보이며 서버 확인 후 같은 위치로 수렴한다.
- 렌더링 속도와 요청 도착 간격이 달라도 기본 이동 속도·스태미나 소모·회피 시간이 유지된다.
- 피격·넘어짐·공격이 추가 입력 없이 종료되며 회피 중복 실행이 없다.
- 기존 벽 충돌, 사슬 제한, 잡힘·전투 불능 제약을 유지한다.

## 단계 2. 공격 판정과 동작 동기화

### 문제와 목표

현재 공격 요청 직후 피해가 발생하며 몸통 근처라는 조건으로 선택 부위에 피해를 준다. 실제 공격 방향과 도달 부위가 결과에 반영되어야 한다.

### 작업

1. 무기별 공격 데이터를 준비·유효 타격·회복 구간으로 정의한다. 피해, 사거리·형태, 부위 피해, 이동 배율, 방향 전환 범위, 다음 입력 허용 구간을 데이터화한다.
2. 서버는 공격 인스턴스와 시작 시각을 생성하고 타격 구간에서 실제 대상 부위의 판정 형상을 검사한다. 한 공격의 대상별 명중 기록으로 중복 피해를 막는다.
3. 클라이언트는 공격 시작 시각과 공격 ID로 동작을 재생한다. 애니메이션 이벤트는 표현 보조로만 쓰고 서버 피해의 유일한 트리거로 쓰지 않는다.
4. 제한된 입력 예약과 다음 공격 연결을 추가한다. 회피·피격 취소 가능 구간은 공통 상태 규칙과 공격 데이터로 정한다.
5. 공격별 이동과 방향 전환을 적용한다. 실제 명중 사건에 타격음·효과·피격 반응을 연결한다. 화면 연출을 위한 정지가 서버 전체 시간을 멈추지 않도록 한다.

### 완료 기준

- 등 뒤나 도달하지 않는 부위에는 공격이 적중하지 않는다.
- 피해 발생 순간이 무기 동작의 타격 구간과 일치한다.
- 한 공격은 허용된 횟수만 적중하고 취소·종료 후 늦은 판정이 남지 않는다.
- 다른 무기 데이터를 연결해도 서버 피해 처리와 입력 처리를 수정할 필요가 없다.

## 단계 3. 애니메이션 전환과 동작 표현

### 문제와 목표

현재 `RaidPlayerVisual`은 상태 전환 때 즉시 애니메이션을 교체하고 구르기·피격에 임시 동작을 재사용한다. 동작의 의미와 실제 이동이 일치해야 한다.

### 작업

1. 캐릭터별 표현 설정으로 행동과 클립을 연결한다. 공통 게임 규칙에서 특정 클립 이름을 제거한다.
2. 이동 속도와 방향으로 걷기·질주를 혼합하고 전환 시간을 설정한다. 이동 속도에 맞게 재생 속도를 조정한다.
3. 구르기·피격·넘어짐·기상·구조·고정 자세·당기기에 맞는 동작을 연결한다. 필요한 원본 동작이 없으면 제작·확보 항목으로 명시하고 임시 동작을 완료로 간주하지 않는다.
4. 공격 재생 위치는 단계 2의 시작 시각과 구간을 따른다. 캐릭터 모델 교체 시 표현 설정만 바꾼다.
5. 루트 모션이 필요하면 변위를 이동 계산에 전달하는 경계를 먼저 정한다. Animator가 서버 위치를 별도로 덮어쓰지 않게 한다.

### 완료 기준

- 걷기·정지·공격·피격·기상 전환이 급격히 끊기지 않는다.
- 표시 동작과 이동 속도·공격 시점이 맞고 모델 변경으로 게임 규칙이 바뀌지 않는다.

## 단계 4. 카메라와 설정 조작

### 작업

1. 자유 시점, 부위 록온, 구조·잡힘 상황의 카메라 정책을 분리한다. 튜토리얼과 전투는 동일한 기본 시점 조작을 사용한다.
2. 부위는 모델이 제공하는 주목 지점을 등록한다. 선택한 부위를 추적하며 파괴·제거 시 유효한 대상으로 복귀한다.
3. 카메라 거리·높이·감도·회전 한계·복귀 속도를 설정으로 분리한다. 보스와 동료를 읽을 수 있도록 기본 구도를 조정한다.
4. 벽 가림은 빠르게 접근·천천히 복귀하도록 처리하고, 플레이어 자신의 충돌체와 시점에 영향을 주지 않아야 할 대상을 필터링한다.
5. 실제 피격·근거리 충격 사건에 화면 흔들림을 연결한다. 강도와 끄기 옵션을 제공한다.
6. 커서 잠금·해제는 공통 플레이/설정 상태에서 관리한다. 언어·감도·흔들림 설정을 한곳에서 조작하고 저장한다. 번역 문구 ID 체계를 이 단계에서 적용한다.

### 완료 기준

- 튜토리얼·전투 진입 시 클릭 없이 회전하고 Esc로 설정 조작과 플레이 시점 사이를 전환한다.
- 록온 부위가 실제 화면의 주목 대상이며 벽 접근·회전 구조에서 구도가 급격히 흔들리지 않는다.
- 한국어·영어 전환 후 주요 안내가 잘리거나 누락되지 않는다.

## 단계 5. 사슬 제약과 협동 피드백

### 작업

1. 입력 이동·사슬 제약·보스 강제 이동의 우선순위를 정의하고 단계 1의 이동 처리에서 최종 변위를 계산한다. 여러 컴포넌트가 별도로 위치를 변경하는 경로를 줄인다.
2. 기존 거리 경계와 제압 규칙은 유지하면서 완충 구간의 감속과 당김 강도를 연속적으로 조정한다.
3. 앵커는 보스의 등록된 부위와 역할로 참조한다. 특정 모델의 고정 로컬 좌표를 공통 사슬 코드에서 제거한다.
4. 장식 사슬은 서버 경로를 따라 보간하고 판정에 영향을 주지 않는다. 긴장·감김·낚아챔을 자세·소리·효과로 알린다.
5. 공동 당기기의 대표 실패 이유를 즉시 수행할 행동으로 보여 준다. 강조가 상태 경계에서 반복 점멸하지 않도록 표시 전환을 다듬는다.

### 완료 기준

- 이동 제한의 시작과 원인을 플레이어가 이해할 수 있다.
- 강제 이동이 중복 적용되거나 표시 사슬 때문에 위치가 바뀌지 않는다.
- 감김·낚아챔·회전 종료 후 기존 규칙대로 복귀한다.

## 단계 6. 보스 판단과 공격 흐름

### 작업

1. 고정 순환 공격 선택을 거리·유효 대상·사슬 상태·직전 기술·재사용 대기 조건에 따른 선택으로 교체한다.
2. 기술별 실행 조건·가중치·전조·회복 시간을 데이터로 정의한다. 공통 선택 로직과 개별 기술 실행을 분리한다.
3. 목표 방향으로 순간 회전하는 처리를 없애고 기술별 회전 속도와 조준 고정 시점을 둔다. 전조가 확정된 뒤 판정 방향을 몰래 바꾸지 않는다.
4. 전조·타격·회복의 몸동작과 효과를 서버 기술 시간에 맞춘다. 전장 경계는 고정 좌표 대신 전장 설정이나 충돌 정보로 제공한다.
5. 현재 다섯 기술과 2페이즈를 먼저 이전한다. 구속 중복 금지·안전 경로·조기 구조·부위 파괴 규칙을 유지한다.

### 완료 기준

- 유효한 대응이 가능한 상황에서 기술을 선택하고 동일 구속을 무리하게 반복하지 않는다.
- 보스의 준비 방향·전조 범위·실제 판정이 일치한다.
- 기술 설정 추가와 개별 실행 구현으로 확장할 수 있고 기존 전체 AI 흐름을 다시 작성하지 않는다.

## 단계별 진행 방식

각 단계는 기존 기능이 동작하는 상태에서 필요한 책임을 추출하고, 한 경로씩 새 구조로 전환한 후 이전 코드를 제거한다. 새 구조와 기존 구조가 동시에 이동·피해·상태를 갱신하지 않게 한다. 앞 단계의 입력·시간·상태 계약을 후속 단계에서 재사용한다.

각 단계 종료 시 두 클라이언트로 해당 변경과 인접 기능을 짧게 확인한다. 수정한 규칙 계산에 한해 필요한 자동 검사를 추가하고, 기존 회귀 실행이 가능한 빌드에서는 관련 사례를 확인한다. 정식 계측 시스템이나 외부 대규모 시험이 완료되어야 다음 단계로 가는 구조는 만들지 않는다.

작업 완료 보고에는 변경한 행동, 유지한 규칙, 실행 확인 범위, 남은 아트·동작 자산 의존성을 기록한다. 플레이 수치 조정과 구조 변경은 구분하여 후속 튜닝의 근거를 보존한다.

- 이후 2단계에서 공격 구간·부위 명중·입력 예약을 구현했고, 3·4단계에서 표현과 카메라를 개선했다.

## 2026-10-31 구현 기록 — 2단계

### 변경 내용

- `RaidWeaponSettings`의 공격 배열로 준비·타격·회복 시간, 피해와 부위 피해, 스태미나 비용, 전방 캡슐 범위, 공격 중 이동 배율·회전 속도·회전 한계, 다음 입력 허용 구간·예약 수명·후속 공격 번호, 회피 취소 가능 시점을 정의했다.
- `CommonWeaponSettings.asset`에 약공격 2연계와 강공격을 연결했다. 기존 약/강 피해·부위 피해·강공격 비용과 총 행동 시간은 유지했다. 이동 배율·회전 제한과 세부 구간은 초기 튜닝값이다. 사용하지 않는 기존 공격 수치 필드는 플레이어와 프리팹에서 제거했다.
- `RaidPlayerCombat`은 요청 시 피해를 주지 않고 공격 인스턴스·시작 시각을 서버에서 만든다. 실제 타격 구간에서만 `RaidAttackHitResolver`가 물리 범위를 검사한다. 화면 애니메이션이나 무기 장식의 좌표가 피해를 확정하지 않는다.
- 실제 겹친 `RaidHurtbox` 가운데 부위를 선택한다. 록온은 닿을 수 있는 부위들 사이의 우선순위로만 사용하며, 멀리 떨어진 선택 부위에 피해를 전달하지 않는다. 한 공격은 한 대상에게 한 번만 적중한다. 공격자와 타격점 사이의 벽도 검사한다.
- `IRaidDamageReceiver`로 공통 명중과 대상별 피해 적용을 분리했다. 현재 보스는 이 경계에서 몸통·코·앞다리의 기존 HP·내구도 규칙을 적용한다. 부위 위치·크기는 `MammothHitboxLayout.asset`의 로컬 박스 자료에 두었다. 새 대상은 인터페이스와 부위 판정체를 연결하고, 모델 교체는 해당 배치 자료를 조정한다.
- 다음 공격은 허용 구간에서 한 개만 예약하며, 서버 기준 수명이 지나면 폐기한다. 피격·넘어짐·잡힘·세션 종료·초기화는 현재 공격과 예약을 취소한다. Esc 설정 조작과 포커스 이탈은 예약을 비운다. 유효한 회복 구간의 회피 취소는 본인 예측에도 적용한다.
- 공격 중 이동·회전 제한을 서버와 클라이언트 예측에서 함께 사용한다. 클라이언트의 공격 동작과 임시 무기 흔들림은 서버 시작 시각과 공격 길이를 따른다. 같은 동작으로 연결되는 연타도 새 공격 시각으로 재생한다.
- 실제 명중을 확정한 뒤 양쪽 클라이언트에 타격점 알림을 보낸다. 기본 효과음·짧은 접점 효과와 보스의 피격 색 반응을 추가했다. 전체 게임 시간을 멈추는 연출은 사용하지 않았다.

### 확인한 범위

- `Chainbound Raid > Validate Combat Rules`: 타격·예약 시간 경계, 닿는 부위 우선 선택, 닿지 않는 선택 부위 배제, 같은 대상 중복 피해 방지, 뒤쪽 빗맞음, 벽 차단(캡슐 시작점보다 가까운 벽 포함), 교체된 피해 자료 전달 확인.

### 남은 확인과 다음 단계

검증 환경은 1단계와 같은 별도 Unity 6000.6.5f1 프로젝트다. 원본 Unity 6000.3.27f1의 전체 씬 빌드와 지연·손실 시험은 포함하지 않는다. 보스 부위는 현재 모델에 맞춘 초기 박스 배치이므로 실제 모델 외곽·움직이는 코와 다리의 세부 정합성을 플레이로 확인해야 한다. 필요하면 본에 `RaidHurtbox`를 연결하는 방식으로 정밀화한다. 기본 접점 효과와 소리는 임시 표현이며 화면·음향 품질 확인은 남아 있다.

이후 3단계에서 캐릭터별 표현 설정과 동작 전환을 구현했다. 전용 클립 확보와 실제 움직임 품질의 수용은 별도 항목이다.

## 2026-10-31 최종 구현 기록 — 3~6단계

### 3단계: 캐릭터 동작 전환

- `RaidCharacterPresentation`에 캐릭터별 클립과 전환 시간·보행 기준 속도를 연결했다. 런타임 플레이어 표현에서 FBX 클립 이름 문자열을 제거했다.
- `RaidAnimationDriver`가 걷기·질주 속도에 맞춰 대기/걷기/질주를 혼합하고 재생 속도를 조절한다. 행동 변경은 이전 자세와 새 자세를 혼합하며, 전환 도중 다른 행동이 들어와도 우세한 기존 자세를 이어받는다.
- 공격은 2단계의 서버 시각으로 재생한다. 루트 모션은 표시용 캐릭터가 서버 위치를 덮어쓰지 못하도록 비활성화했다. 비활성화·모델 교체 시 재생 그래프를 정리한다.
- 구조 유지 입력도 동기화해 다른 클라이언트에서 구조 표현을 연결할 수 있도록 했다.
- 현재 없는 구르기·피격·넘어짐·잡힘·기상·구조 전용 클립은 빈 슬롯과 임시 자세 표현으로 남겼다. 질주나 감정 표현을 해당 행동의 완성된 클립으로 간주하지 않는다. 슬롯에 전용 클립을 넣으면 공통 판정 코드를 바꾸지 않고 교체할 수 있다.

### 4단계: 카메라·입력·설정·언어

- `RaidTargetFocus`가 실제 부위 판정체의 범위를 제공한다. 록온은 네트워크 대상 참조와 선택 부위를 사용하고, 파괴된 부위는 서버에서 몸통으로 복귀시킨다.
- 카메라 거리·높이·회전 한계·충돌 필터·복귀 속도·로비 구도를 `PlayerCameraSettings.asset`으로 분리했다. 큰 부위의 범위에 맞춰 록온 거리를 조절한다.
- 벽에 가까워지면 거리를 즉시 줄이고, 벗어나면 설정 속도로 복귀한다. 자신과 동료의 충돌체는 카메라 가림으로 처리하지 않는다. 흔들림은 본인의 실제 피해 사건에 연결하며 멀리 떨어진 보스 기술만으로 발생하지 않는다.
- `RaidInputController`와 `RaidInputContext`가 커서·설정 상태를 관리한다. 카메라 구현을 교체해도 입력 상태 관리가 남는다. 튜토리얼/전투 진입 후 마우스로 바로 회전하고, Esc로 설정과 플레이를 전환한다.
- 언어·마우스 감도·흔들림·글자 크기를 하나의 설정 패널에 모으고 저장한다. 기존 HUD의 중복 옵션 버튼을 제거했다.
- 화면 문구를 `RaidLocalization.json`의 안정적인 ID와 한국어/영어 자료로 옮겼다. 동적 값은 서식 인수로 전달한다. 실행 중 영문 부분 문자열을 바꾸던 방식은 제거했다. 열거형 값은 정확히 일치하는 문구로만 변환한다.

### 5단계: 사슬과 이동 통합

- 입력 이동과 사슬 제한, 사슬 당김, 보스 강제 이동을 플레이어의 한 `CharacterController.Move` 경로에서 처리한다. 강제 이동이 있으면 해당 속도 상한의 이동을 우선하며, 없으면 제한된 입력 이동과 사슬 당김을 합산한다.
- 강제 이동 상태를 이동 스냅샷에 포함해 본인 예측과 재적용에도 사용한다. 사슬 자체는 더 이상 플레이어 위치를 직접 갱신하지 않는다.
- 7/8/9m 경계는 유지했다. 완충 구간에서 장력 표시를 점진적으로 높이고 과긴장 당김도 장력에 따라 시작한다. 시각 사슬은 위치를 보간하고 여유일 때 처짐을 표현하며 판정에는 영향을 주지 않는다.
- 감김점·코 잡기점·구조 위치를 `MammothAnchorLayout.asset`으로 옮겼다. 플레이어 허리 연결 위치도 별도로 지정할 수 있다. 클라이언트의 플레이어 목록은 생성/해제 등록으로 관리한다.
- 장력의 소리·자세 반응을 추가했다. 공동 당기기 실패 안내는 HUD와 튜토리얼이 같은 문구 ID를 사용해 바로 수행할 행동을 표시한다.

### 6단계: 보스 판단과 공격 흐름

- 고정 공격 순서를 제거했다. `MammothMoveSet.asset`의 거리·시작 각도·페이즈 가중치·재사용 대기·사슬/장력 조건으로 서버가 기술을 고른다. 같은 구속 기술 반복과 구속 중첩을 막고 구속 후 휴식 시간을 적용한다.
- 적절한 공격이 없고 멀리 있으면 접근하고, 조준 방향으로 점진적으로 회전한다. 기술 전조가 시작되면 표시 방향을 고정하며 즉시 방향을 바꾸지 않는다.
- 공통 상태 진행과 다섯 기술의 시작/유지 실행을 `RaidBoss`와 `RaidBossMoves`로 분리했다. 새 기술은 자료와 실행 핸들러를 추가하는 경계로 확장한다.
- 돌진은 실제 장애물과 `RaidArenaBounds.asset`의 전장 범위를 검사한다. 공통 실행 코드의 고정 전장 좌표를 제거했다.
- 전조·유효 단계·회복의 시작 시각과 길이를 동기화한다. `MammothPresentation.asset`이 기술별 클립과 접촉 시점을 제공하며, 보스 표현도 공통 혼합 재생기를 사용한다.
- 관련 부위 파괴 시 회복 빈틈을 늘린다. 코 파괴로 이후 낚아채기의 공동 대응 자체가 사라지지 않도록 코 잡기점의 유효성을 내구도와 분리했다. 앞다리 감김 해제와 기존 2페이즈·구조·안전 거리 규칙은 유지한다.
- 낚아채기·회전 전용 보스 동작은 아직 없다. 기존 코 휘두르기를 완성된 대체 동작으로 사용하지 않고, 전조와 상태/구조 표식을 제공하면서 전용 클립 연결을 기다린다.

### 최종 검사 범위

- `Chainbound Raid > Validate Gameplay Improvements`로 이동·공격 검사와 실제 자세 혼합, 동작 복귀, 카메라의 벽/자기 충돌체 필터, 번역 ID/서식 인수/언어 선택, 캐릭터·보스 자료 연결, 보스 기술 선택 조건을 확인했다.
- 기존 사슬 거리·상태 경계와 공동 당기기 규칙의 100회 반복 검사도 통과했다.
- 전체 자산과 전투 씬을 별도 검증 프로젝트로 복사해 Windows 개발 클라이언트를 빌드했다. 같은 실행 파일의 서버 모드로 전용 권위 프로세스를 실행하고 클라이언트 두 개를 연결해 튜토리얼, 보스 기술 대응, 누적 다운 구조, 승리의 네 회귀 사례를 확인했다. 보스 검사는 순간 회전 가정을 제거하고 전조 후 정렬 및 회전 후 실제 구조 지점을 검사하도록 갱신했다.
- 이 환경은 설치된 Unity 6000.6.5f1과 임시 호환 처리 환경이다. 원본 `ProjectSettings`/`Packages`와 기준 Unity 6000.3.27f1은 변경하지 않았다. 원본 버전의 빌드 통과나 전용 서버 빌드 산출물 생성까지 보증하는 결과는 아니다.

### 남은 자산·사람의 확인 항목

코드 계획 1~6단계는 반영했다. 다음은 코드 구현 완료와 구분한다.

1. 플레이어의 구르기·피격·넘어짐·기상·잡힘·구조 전용 클립과 보스 낚아채기·회전 클립 제작/확보 및 연결.
2. 공격 접촉 정규화 시점, 보스 부위 박스와 연결점, 보행 기준 속도, 시점 거리·복귀 속도를 실제 모델과 두 사람 플레이에 맞춰 튜닝.
3. 한국어/영어 화면의 잘림·가독성, 벽/계단의 시점, 회전 중 구조 안내, 타격 효과·소리의 현장 확인. 자동 검사는 화면 품질 수용을 대체하지 않는다.
4. 원본 Unity 6000.3.27f1에서 정식 개발 클라이언트·전용 서버 빌드 및 재확인. 이번 별도 검증 실행 파일은 배포용 빌드로 사용하지 않는다.
5. 지연·손실·장시간 접속, 기술별 20회 이상 반복, 외부 사용성 시험과 정식 계측은 기존 결정대로 후순위다.
